## Phase 0：需求釐清（7/15 上午，2-3小時，寫Day1之前）

**不要一開始就 `npm create` 然後直接寫。** 很多人第一天建專案、第三天全部重拆，就是因為需求沒想清楚。花2-3小時把下面這些定案：

- [ ] 有哪些頁面？（Step1~4、Success、AdminList、AdminDetail）
- [ ] 每頁有哪些欄位？
- [ ] 每個欄位的驗證規則是什麼？
- [ ] Pinia store 要放什麼資料？結構長怎樣？
- [ ] Component 怎麼拆？（哪些是共用的，例如進度條、確認彈窗）
- [ ] 畫一張流程圖，例如：
  ```
  App
   └→ Step1 → Step2 → Step3 → Confirm → Success
  ```
  可以手繪拍照，或用 Excalidraw / FigJam，不用精美，重點是想清楚。

**這一步做完，後面Day1~Day6的速度會明顯變快**，因為架構跟資料形狀都已經定案，不會邊寫邊改。

## Phase 1：專案衝刺（7/15 – 7/29）

原6天版拆分為11個工作天，中間穿插2個週末做緩衝／整理，避免趕工留坑。

**本版的調整（累積自v2 + v3）：**
1. **JS暖身跟著當天任務走，不照固定課表**：關聯性弱的暖身就跳過。
2. **驗證邏輯「先手寫、再重構」**：先用原生JS寫一版驗證邏輯確認理解，再重構成Zod+VeeValidate。
3. **Admin頁面獨立一天，收尾日只做收尾**：避免最後一天塞爆。
4. **每天結束前：5分鐘口頭錄音 + 4題反思**：練習面試講解能力。
5. **（新增）手寫驗證日改用原生DOM操作**：7/17、7/21、7/23這三個「先手寫」的天數，刻意不用 `v-model`，改用 `querySelector` 抓 `input.value`、手動掛 `addEventListener('input', ...)`、用 `classList.add/remove` 切換錯誤樣式，補回《60天計畫》Day8-14 DOM/事件流的實作經驗（Vue開發時通常會被框架取代掉，容易變成不熟）。
6. **（新增）進階陣列方法刻意練習**：7/20、7/28 明確安排 `map`、`some`、`every`、`includes` 的實際使用情境，而不是只有 `filter/find`。
7. **（新增）API錯誤處理與狀態碼分類**：7/27送出流程加入 `try/catch`，並依模擬的HTTP狀態碼（200/401/404/500）分別顯示對應UI訊息，補回《60天計畫》Day36-40的防錯訓練，而不是只做「送出成功」這個happy path。**500的錯誤狀態用inline訊息呈現即可（7/27已涵蓋），不用額外做一個獨立的500錯誤頁面路由**——避免重複展示同一個能力、浪費時間。
8. **（新增）404錯誤頁**：塞進7/29收尾日的UI打磨項目，成本很低（Router catch-all + 靜態元件），避免部署後亂點連結出現空白頁。

- **投遞**：每週目標投遞 10-15 家（可依回覆率調整）
- **面試準備**：當週有面試 → 優先準備該公司資料、模擬問答；無面試 → 持續精進自我介紹與專案講解流暢度
- **技術維持**（每週2-3次，每次1小時內即可）：
  - 複習重點可對照附件1《JavaScript 60天學習計畫》中 map/filter/find、async/await、fetch/AJAX 相關段落做「重點複習」而非整輪重跑
  - 延續Phase1的口頭練習習慣：練習講解自己專案裡的技術決策
  - **（新增）開源專案拆解任務**：每2週安排一次，挑一個簡單的Vue3開源專案，練習找出頁面入口、API service封裝位置、共用元件怎麼被使用，寫一篇「閱讀筆記」（格式可沿用附件1的頁面閱讀筆記模板）。這是補回《60天計畫》Day43-60「閱讀既有專案」的實戰經驗——FlowForm Summit 2026是從0到1新建，跟「維護別人寫的舊程式碼」是不同的能力，求職後大機率會遇到後者

## 提醒

- Phase 0 花的2-3小時看似「還沒開始寫code」，但能省下後面重拆架構的時間，是划算的投資。
- Phase 1 雖然時間拉長了，但保留週末緩衝是刻意的：裸辭後的復原期需要，不要用「6天版」的高壓節奏硬撐2週。
- Admin頁面跟收尾日分開，是為了避免最後一天塞太多任務、Bug一直修到README跟部署都沒做完。
- 手寫驗證日改用原生DOM操作，是刻意的：Vue開發久了容易忘記`v-model`底層到底做了什麼，面試被問「Vue雙向綁定原理」時，有實際手寫過DOM事件的經驗會答得更扎實。
- 開源專案拆解任務是為了補「維護舊專案」的能力——這跟「自己從0到1做專案」是不同的肌肉，求職進去後幾乎一定會遇到前者。
- Phase 3 的技術維持不是重新學，是「保持手感」，時間抓短即可，避免排擠投遞與面試準備時間。
- 每個Phase交界處都建議留半天做心態/進度盤點，而不是無縫銜接。
